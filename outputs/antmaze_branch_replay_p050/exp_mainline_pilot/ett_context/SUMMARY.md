# Step 0 (simulator-paired one-step ETT, AntMaze V6): the same-context expert advice IS reconstructable; one-step motion is deterministic to float precision

Status: an oracle-supervised engineering stage (the advice a_b at the
branch contexts comes from the privileged teacher run inside the
simulator), not offline identification.  `REPORT.md` has every number;
`audit_v6_ett_context.py` the procedure.  No training.

## What is established

1. **Hidden context and intent** for every d05 episode.  Sidecars exist
   for collection seeds 606 / 610 / 611 (497 episodes); for 607-609 (503
   episodes) the collector's draws were regenerated by replaying its
   fixed-order RNG consumption (env seeded with the collection seed, one
   reset per episode in order; the route coin from its own stream) and
   validated EXACTLY on the three available seeds (intent, U1 / U2, t0_1 /
   t0_2 and the rock jitter: 1,000 / 1,000 each, jitter max diff 0.0).
   The intent is the coin; it is never taken from the realised route (in
   d05 the two agree in 1,000 / 1,000; in the pool two episodes differ).
2. **The teacher's internal state is a deterministic function of
   reconstructable inputs.**  A fresh teacher given the intent, the logged
   observations and the original timetable reproduces every one of the
   267,481 logged torques bit-exactly, the per-step holding zone
   (132,228 / 132,228 rows) and the zone decisions (497 / 497), and its
   consultation steps equal the recorded mouth steps (497 / 497).  No
   unlogged randomness enters the advice.
3. **a_b at the branch contexts.**  Each pilot branch redraws the hidden
   context (its own hazard seed; regenerated here and matched to the
   branch file for all 53,747 anchors).  The teacher state at t is
   reconstructed from the logged history (leg, trail, nudges, step,
   intent); the two zone latches are RE-DERIVED by the teacher's own rule
   at the recorded consultation steps under the new timetable; then the
   teacher is asked at (s_t, new timetable, t).  Nothing is derived from
   the query torque or the realised route.  Under the ORIGINAL timetable
   this reconstruction returns a_b == a_q exactly at all 53,747 anchors.
   Under the redrawn timetable, anchor-weighted: diagonal 0.829, off_hold
   0.093 (the teacher would hold, the query drives), off_release 0.079
   (the teacher would drive, the logged torque is a hold), off_other 0.
   The off-diagonal rows sit where the confounder acts -- the mouths and
   the hazard bands (zone 1 anchors 28 % off_hold, zone 2 19 %; the start
   region, the goal area and the far-route legs 100 % diagonal) -- and
   they carry the outcome: branch death share 0.649 under off_hold vs
   0.273 diagonal vs 0.058 off_release.
4. **One-step motion is deterministic given (s, torque), independent of
   the hidden context, to float precision** (hypothesis tested, not
   assumed): restoring the logged state with the ORIGINAL context and
   executing the logged torque reproduces the logged next state with
   max |diff| median 2.4e-7, p99 1.9e-6 (2,235 / 2,236 rows within 1e-5
   outside bursts; inside bursts max 9.5e-7 over 764 rows); the branches'
   first post-query row (same state, same torque, DIFFERENT hidden
   context) equals the logged next state within 1e-5 in 53,744 / 53,747
   anchors; the 3 exceptions are angular-velocity discrepancies of
   0.04-0.16 at ordinary positions (contact-solver sensitivity; xy
   identical).  Rocks never displace the ant in the step they hit: the
   hidden context enters only through the death (onset) event.

## What is missing / limited

* Onset labels exist only in the simulator branches (15,612 deaths of
  53,747 branches); the d05 log has no failures.  Every branch that
  ended after the query step (194) is a timeout / success, none a death,
  so no onset label sits on a logged query row itself.
* a_b along the branch rows (j >= 1, the start agent's torques) will be
  the teacher's advice with its relay state evolved along the branch path
  under the redrawn timetable (Step 1) -- the same construction, applied
  step by step; it is the expert's advice for that path, not a path the
  expert would have produced.
* Fork query coverage stays closed: the only queries are the logged
  torques (row 0) and the start agent's torques (rows >= 1).

## Decision

The label construction of Step 1 proceeds: (s, a_b, a_q, s', onset) from
the logged rows (diagonal) and the branch rows (advice walked along the
branch), cross-fitted by source episode; the one-step model of Step 2
is a deterministic motion regression F(s, a_b, a_q) -> s' plus an onset
head, with the preflight gates adapted from the PointMaze protocol.

## Step 1: the supervision file (`supervision.npz`, `supervision.json`; `build_v6_ett_supervision.py`)

Every valid branch transition (7,648,612 of 7,702,359 rows; the last row of
each branch has no successor) carries the teacher's advice walked along
the branch under its redrawn timetable (state reconstructed at the
anchor, latches re-derived at the recorded consultation steps, then the
relay evolved along the branch's own rows, the rule consulted when the
path first stands at a mouth).  Row 0's advice equals Step 0's a_b for
all 53,747 anchors (max diff 0.0).  Composition: root rows diagonal
44,580 / off_hold 4,894 / off_release 4,273; agent rows (j >= 1, the
start agent's torques) off_hold 310,781 / off_other 7,284,084 (median
max|a_b - a_q| 0.93 -- the agent's torque is never the relay's).  Onset
= the fatal transition of a dying branch: 15,612 (= the deaths), of
which 15,600 fall on off_hold rows (the teacher would have been holding
because the timetable is unsafe) and 12 on off_other rows, none on a
diagonal row; within the hold rows the per-step onset rate is ~4.9 %
(timing inside the band is not identified by the visible state -- that
is what the onset head has to model).  The logged rows (267,481) are all
diagonal with onset 0.  Folds by source episode (3; 17,843 / 18,235 /
17,669 anchors).  Nothing was missing at this step, so the labels were
constructed; the two limits stand: onset labels only from the branches,
and no fork query coverage.
